# Network Visibility Walk Through SIEM

Network log sources can be divided into two logical parts:

- Host-Centric Log Sources: these are events captured within or related to a specific host, they are generated by Windows Event Logs, Sysmon, OSQuery etc. Examples of these are users accessing files, PowerShell executions etc.
- Network-Centric Log Sources: these are generated when hosts communicate across the internet, examples are SSH connections, FTP transfers or web traffic.
    
<br/>SIEM can put all these logs in a central location and allow you to search and correlate events between them.

# Log Sources and Log Ingestion

Windows records all events and assigns them IDs through the Event Viewer, these logs can all be forwarded to a SIEM solution. Linux stores all logs which can be ingested into a SIEM from various locations:

- `/var/log/httpd`: all HTTP response/request error logs
- `/var/log/cron`: events related to cron jobs
- `/var/log/auth`.log and /var/log/secure: authentication logs
- `/var/log/kern`: kernel events
- `/var/log/apache`: web server logs
    
<br/>Each SIEM has its own way of ingesting logs, some common methods are:

- Agent/Forwarder: a lightweight tool installed on the endpoint to capture all logs
- Syslog: widely used protocol to collect data from various systems
- Manual Upload: manual upload of specific log data for analysis
- Port-Forwarding: can be configured to listen on a certain port which endpoints forward data to

# Why SIEM

SIEM capabilities:

- Correlation between events and log sources
- Visibility over host and network centric logs
- Allows analysts to investigate threats
- Hunt for specific threats not identified by rules in place
- Within a SIEM, the analysts are responsible for:
- Monitoring and investigating
- Identifying false positives
- Tuning rules causing noise or false positives
- Reporting and Compliance
- Identifying blind spots and covering them

# Analysing Logs and Alerts

Dashboards are the most important component of any SIEM:

- Alert Highlights
- System Notifications
- Health Alert
- Failed Login Attempts
- Events Ingested Count
- Rules Triggered
- Domains Visited
    
<br/>Correlation rules can be created to help with threat detection, these are logical expressions which trigger, for example, if a user fails 5 logins in 10 seconds trigger an alert.
